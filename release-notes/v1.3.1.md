# logforge 1.3.1

A one-line fix for a header that 1.3.0 broke for some compilers.

## What was wrong

`SpdlogBackend::Config`'s constructor listed `console` before `name` in its
initialiser list while declaring `name` first. GCC reports that as `-Wreorder`,
and under `-Werror` the header fails to compile; MSVC reports nothing, which is
why the release went out with a green Windows build and a red CI. Members are
initialised in declaration order regardless, so 1.3.0's behaviour was correct --
it just could not be compiled with warnings as errors, and not at all with
`-Wall -Wextra -Werror` on GCC.

## What to do

Use 1.3.1. The API is identical to 1.3.0: no source change, no ABI change, the
same `Config` fields in the same order.
