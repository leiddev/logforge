# logforge 1.4.0

The backend learns to start a daemon: build one sink at a time, create the
directory its file lives in, and install both defaults in one call.

Everything here is additive. The constructor keeps its contract -- a broken
configuration throws at startup -- and no existing call site changes.

## What the consumer kept rewriting

A service that logs to a file, a console and a UDP collector has three
destinations, and any of them can fail for a reason that has nothing to do with
the other two: the directory does not exist, the disk is full, the UDP address is
misconfigured. `SpdlogBackend` built all of them in one go, so a program that
needed to come up anyway had to write the ladder itself -- catch, drop the file,
retry; catch, drop the UDP too, retry -- and then decide what to say about it.

The one thing that must not happen is the retry succeeding *silently*. The
consumer this release was written for printed

```
Init logger...[name: xec, level: debug, file: ./logs/xec-log.txt, ...]
```

whether or not that file had been opened. An operator reading the log believed
the file was there.

## What 1.4.0 adds

### `SpdlogBackend::open(config, report)`

The same backend, one destination at a time:

```cpp
logforge::SpdlogBackend::Report report;
std::unique_ptr<logforge::SpdlogBackend> backend =
    logforge::SpdlogBackend::open(config, &report);

if (!backend) {
    // nothing could be built at all -- StderrLogger is the last resort
}
if (!report.file.empty()) {
    LOGFORGE_LOG_WARN("file sink dropped: {}", report.file);
}
```

A sink that cannot be opened is named in `report` (the string is spdlog's own
exception text, which is the most specific thing a program can print) and the
others are kept. `nullptr` comes back only when no destination at all could be
built; a configuration that names none still gets a console, as the constructor
always did.

`open()` deliberately does not print the report. Only the caller knows where a
warning can still be seen, and a library that printed it would be writing to a
sink it may just have failed to build. The `Report` is the message; printing it is
the program's first act.

### `Config::create_directories`

Before opening the file, walk the path and create each directory, on Windows and
on POSIX. Off by default: a library should not create directories it was not asked
to create. On for a program whose configuration ships `logs/pipeline.log`, which
otherwise dies on its first start and works on the second.

### `SpdlogBackend::install_as_default()`

Sets logforge's default (the macros and the ambient binding) and spdlog's registry
default (its free functions, and any dependency that logs through spdlog's global
logger). Two calls, and the half-installed state -- everything that went through
spdlog landing on its built-in console logger instead of the file -- is invisible
until someone notices the missing lines.

### A destroyed backend leaves no default behind

If a backend is the process default and is destroyed, logforge's default is
cleared instead of pointing at freed memory while the program shuts down.

## What to do

Nothing, unless one of the three new things was the reason you were about to write
it yourself. `Config` gained one field, `create_directories`, defaulted to
`false`: every existing configuration behaves exactly as it did, and the
constructor still throws on a broken one.
