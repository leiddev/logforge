# logforge 1.4.2

The tests catch up with the promises the library makes, and the one promise they
found broken on Windows is fixed.

No API change and no call site changes. The only build change is one compiler
flag MSVC needed all along.

## Why this release

Every component had its normal path covered -- the renderer, the macros, the
thread binding, both backends -- and almost nothing had its failure paths. The
gaps were the ones that matter, because they are the ones nobody looks at until
a daemon comes up half configured:

- `create_directories` was tested on one absolute path. The case the feature
  exists for, `logs/pipeline.log` relative to the working directory, was not,
  and neither was a bare file name with no directory at all.
- `open()` was tested losing a file sink. A UDP destination spdlog cannot build
  was not, the constructor was never tested throwing at all, and a `Report` was
  never tested at the moment nothing went wrong.
- `<logforge/spdlog_backend.hpp>` promises that a translation unit which only
  installs a backend compiles no spdlog header. Nothing checked it, because every
  test that touched the backend included spdlog itself.
- The compat header's `#ifndef` guards exist so that `LOG_INFO` from glog or
  syslog wins over ours. That is its whole reason for being a separate header,
  and no test defined a name before including it.
- Neither the macro's "logger and level are evaluated once" nor the backend's
  "`log()` is called from several threads" had a test.

## What the tests found

### MSVC compiled `ScopedBinding` without unwinding

The build target that carries this repository's own compiler flags never passed
`/EHsc`, so MSVC used its default `/EHs-`. Under that setting a local object is
not destroyed while an exception unwinds.

`ScopedBinding`'s destructor *is* that object. Its contract -- stated in the
header, in `LOGGING.md` and in the README -- is to restore the previous logger on
every exit path, including an exception. On GCC and Clang it did. On Windows it
silently did not: a thread that threw out of a bound scope kept writing to the
logger it had bound, for the rest of the process. Nothing failed, nothing
warned, and the two new exception tests in `ambient_test.cpp` were the first
thing to notice.

`/EHsc` is now part of `logforge_build_flags`. The flag reaches this
repository's own targets, so a consumer that links `logforge::core` is
unaffected -- except that it no longer sees a `C4530` warning from our headers.

### `set_pattern("")` is not "reset the pattern"

`Config::pattern` treats an empty string as "keep spdlog's default", and the
header documents it that way. `set_pattern()` passes its argument to spdlog
unchanged, and spdlog compiles the empty string into a formatter with no fields:
the body of every record is dropped and only the pattern's newline is written.

That asymmetry is now in the suite rather than in a log that stopped being
readable. The behaviour is unchanged in this release -- making `set_pattern("")`
mean "restore the default" is a decision for a later version, and one that needs
the default to be remembered first.

## What was added

Three new test files, and forty new cases in the three that existed -- 62 tests
before, 102 after:

| File | What it pins |
|---|---|
| `format_boundary_test.cpp` | the 512 width and 64 precision limits on both sides, hex with a width, zero padding around a sign, unclosed and doubled braces, specifiers that parse in part |
| `legacy_names_test.cpp` | a `LOG_INFO` the caller defined survives the compat header; `LOG_ERR` and `LOG_CRITICAL` are different levels |
| `spdlog_forward_decl_test.cpp` | a TU compiled with no spdlog include directory at all |
| `macro_test.cpp` | single evaluation, `LOGFORGE_LOG_AT_TAGGED`, a null tag, a disabled statement that does not call `log()` |
| `ambient_test.cpp` | a binding restored when its scope throws, and two of them unwound by one exception |
| `spdlog_backend_test.cpp` | `create_directories` on a bare name, a relative path and an existing directory; the constructor throwing where `open()` reports, for a file and for UDP; a UDP destination missing its host or port; a null `Report`; console and file at once; the component prefix; embedded zero; a null text; a destroyed backend leaving a surviving default alone; spdlog outliving the backend; four threads whose prefixes must not mix |

The forward-declaration test needed its own link line to mean anything: naming
`logforge::spdlog` puts spdlog's include directory on the compile line through
its `PUBLIC` dependency, so the target links the two library files by path
instead. Adding an `#include <spdlog/spdlog.h>` to the header and watching that
target -- and only that target -- fail to compile is how the check was verified.

## What to do

Update and run your tests. If you build with MSVC and your own flags also omit
`/EHsc`, the fix does not reach you: add it to your target, or the same
exception-path bug is still there in your code.
